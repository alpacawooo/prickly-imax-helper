# Prickly carousel design rules

이 문서는 `prickly.ai` 캐러셀을 만들 때 지켜야 하는 시각 규칙이다. 목표는 정돈된 템플릿이 아니라, 사람이 소재를 보고 장면별로 편집한 결과다.

## 보존 계약

- 승인된 메시지 순서, 장수, 사실관계, CTA는 임의로 바꾸지 않는다.
- 공식 스틸과 실제 제품 화면을 우선 사용한다.
- 실제로 존재하지 않는 브라우저, 터미널, 티켓, 성공 화면을 만들지 않는다.
- 기능을 더 많아 보이게 하거나 예매 성공을 보장하는 표현을 추가하지 않는다.

## 구성 원칙

- 한 슬라이드에는 하나의 중심 장면과 하나의 주된 문장만 둔다.
- 실제 스틸 또는 제품 화면이 전체 면적의 60~75% 이상을 차지한다.
- 모든 슬라이드에 같은 `이미지 위 + 설명 아래` 구조를 반복하지 않는다.
- 텍스트 위치는 장면의 시선, 인물 방향, 비어 있는 공간에 따라 결정한다.
- 첫 장, 문제 장, 제품 장, 결과 장, CTA 장의 밀도와 리듬을 다르게 만든다.
- 중앙 정렬은 CTA처럼 이유가 있는 장면에서만 사용한다.
- 참고 자료에서는 문제 제기, 시선 흐름, 결과 증명의 원리만 가져온다. 고유 레이아웃과 자산은 복제하지 않는다.

## 금지 항목

- 동일한 크기의 카드와 박스를 반복하는 구성
- 기본형 Bento 그리드와 기능 카드 나열
- 불필요한 pill, badge, kicker, 아이콘, 장식용 영문 라벨
- 모든 영역을 둥근 사각형으로 감싸는 처리
- 가짜 브라우저 크롬, 가짜 터미널, 가짜 휴대폰 목업
- 장식 목적의 그라데이션, 그림자, glow, parallax
- 내용을 설명하지 않는 ambient motion
- 매 장 같은 위치에 반복되는 로고와 페이지 장식

## 타이포그래피

- 한 화면의 글꼴은 한 계열을 사용하고 굵기 차이로 위계를 만든다.
- 표지 문구는 모바일 썸네일에서도 한 번에 읽혀야 한다.
- 본문 설명은 두 문장 이하로 제한한다.
- 강조색은 Prickly red 하나만 사용하고, 한 화면에서 한 번만 쓰는 것을 기본으로 한다.
- 영문은 제품 상태값이나 실제 UI에 존재할 때만 사용한다.

## 제품 화면

- 설정, 감시, Notion 화면은 실제 캡처나 실제 녹화를 사용한다.
- 개인정보는 마스킹하고, 상태값은 사실인 값만 보여준다.
- 화면 위 강조는 한 번에 한 영역만 사용한다.
- 강조선은 얇고 짧게 유지하며, 기능 카드로 다시 그리지 않는다.
- 화면이 복잡하면 전체를 축소하지 말고 필요한 부분을 자연스럽게 확대한다.

## 모션

- 정지 스틸은 6~10초 동안 1.02~1.05배의 느린 확대만 허용한다.
- 제품 화면의 커서는 실제 작업 순서대로 이동하고 순간이동하지 않는다.
- 진입 모션은 `ease-out`, 퇴장 모션은 필요할 때만 빠르게 사용한다.
- UI 강조와 자막 전환은 대체로 300ms 이내로 끝낸다.
- 동시에 여러 요소를 움직이지 않는다.
- 모션이 없어도 같은 내용을 이해할 수 있어야 한다.

## 최종 검수 질문

1. 첫 1초에 무엇을 봐야 하는지 분명한가?
2. 실제 소재보다 장식이나 UI 프레임이 더 눈에 띄지 않는가?
3. 이전 장의 템플릿을 복사해 내용만 바꾼 장이 있는가?
4. 같은 크기의 박스가 두 개 이상 반복될 필요가 있는가?
5. 사람이 편집한 장면처럼 보이는가, AI가 동일한 상자를 조립한 것처럼 보이는가?
6. 움직임이 내용을 설명하는가, 단지 화면을 바쁘게 만드는가?
7. 제품 화면과 문구가 실제 동작 및 안전 경계와 일치하는가?

하나라도 만족하지 못하면 출력 전에 다시 편집한다.
