# Prickly IMAX Helper 0.1.0 비공개 파일럿 운영표

이 문서는 운영자용이다. 참가자에게는 Notion의 `3분 시작` 페이지만 전달한다. 개발자가 옆에서 명령을 대신 입력하지 않아도 완료되는지를 확인하는 것이 파일럿의 목적이다.

## 참가자 구성

세 명 모두 서로 다른 CGV 계정을 사용하고, 같은 공인 IP에서는 동시에 한 명만 실행한다.

| 참가자 | 운영체제 | 네트워크 | 메일 앱 | GitHub 초대 | 결과 |
|---|---|---|---|---|---|
| A | macOS | 독립 공인 IP | Apple Mail | 대기 | 대기 |
| B | macOS | 독립 공인 IP | Apple Mail | 대기 | 대기 |
| C | Windows 10/11 표준 사용자 | 독립 공인 IP | 클래식 Outlook | 대기 | 대기 |

Windows의 새 Outlook만 사용하는 참가자는 0.1.0 파일럿 대상에서 제외한다. 관리자 계정이나 관리자 PowerShell로 설치 성공을 대신 증명하지 않는다.
세 참가자는 수신 서비스를 Gmail·네이버 메일·iCloud Mail·기타 중 서로 다르게 선택해 운영체제와 수신 주소 제공자가 분리되어도 테스트 메일과 결과 알림이 도착하는지 확인한다.

## 초대 전 운영자 확인

- [ ] 승인 메타데이터에 승인일, 허가 범위, `public_ip`, 초당 최대 1회, 공개 참조값 또는 비공개 원문 SHA-256 지문이 있다.
- [ ] GitHub tag와 release가 정확히 `0.1.0`이다.
- [ ] macOS와 Windows 아카이브 및 각 `.sha256` 파일 네 개가 release에 첨부돼 있다.
- [ ] GitHub Actions의 macOS와 Windows 작업이 모두 통과했다.
- [ ] Notion 페이지의 릴리스 링크가 실제 비공개 release를 가리킨다.
- [ ] 24시간 soak가 429·중복 감시·로그인 손실·큰 메모리 증가 없이 통과했다.
- [ ] 참가자별 GitHub 비공개 저장소 초대를 보냈다.

## 참가자별 완료 증거

참가자는 Notion만 보고 아래 항목을 순서대로 수행한다. 운영자는 화면을 대신 조작하지 않는다.

- [ ] GitHub 초대 수락
- [ ] 자기 운영체제의 아카이브와 `.sha256` 다운로드
- [ ] 한 줄 명령에서 체크섬 `OK` 또는 불일치 없음 확인
- [ ] 사용자 범위 설치 완료
- [ ] 전용 Chrome에서 본인이 CGV 로그인
- [ ] Gmail·네이버 메일·iCloud Mail·기타 중 본인의 수신 서비스를 선택하고 주소 입력
- [ ] 영화·극장·IMAX 형식·요일별 시간·연속 좌석 수·허용 열·양끝 제외율·좌석 우선순위를 확인하거나 수정
- [ ] 관람권 수량·잔액 0원·중복 금지·기존 예매 변경/취소 금지 조건 확인
- [ ] 자동 좌석 선택과 조건 일치 시 1회 제출에 직접 동의
- [ ] 동일 공인 IP 한 대 실행에 직접 동의
- [ ] Apple Mail 또는 클래식 Outlook을 통해 선택한 수신 주소로 테스트 메일 수신
- [ ] 무클릭 `dry-run` 통과
- [ ] `status`가 `armed`임을 확인
- [ ] `doctor`가 필수 검사를 통과
- [ ] `diagnose` 결과에 이메일·고객번호·관람권 번호가 없는지 확인
- [ ] `stop`으로 중단
- [ ] 검증된 같은 버전 update 실행 후 설정·전용 Chrome 프로필 유지 확인
- [ ] 다시 시작 및 `armed` 확인
- [ ] uninstall에서 프로그램만 삭제하고 설정·로그인 프로필 보존 확인

## 개인정보 없는 증거 파일

운영자는 저장소 밖의 개인 폴더에 빈 양식 세 개를 만든다. 이름·이메일·IP 주소·진단 원문은 기록하지 않는다.

```bash
python3 scripts/pilot_audit.py init --output "$HOME/prickly-pilot-evidence"
```

각 참가자의 `diagnose` JSON은 운영자가 내용을 보관하지 않고 로컬에서 SHA-256만 계산해 `redacted_diagnose_sha256`에 기록한다. 설치 아카이브의 SHA-256도 같은 방식으로 기록한다. 모든 체크가 끝나면 아래 명령이 세 참가자, macOS·Windows 포함, Windows 표준 사용자, 서로 다른 수신 서비스, 전 단계 완료 여부를 검사한다.

```bash
python3 scripts/pilot_audit.py verify --input "$HOME/prickly-pilot-evidence"
```

`"ok": true`가 아니면 베타 성공으로 표시하거나 릴리스를 게시하지 않는다. 이 폴더는 GitHub에 올리지 않는다.

## 실패 보고 양식

비밀번호, 전체 화면 캡처, CGV 고객번호, 관람권 번호, 쿠키, 카드정보는 받지 않는다. 참가자는 아래 정보만 보낸다.

```text
참가자: A/B/C
운영체제 및 버전:
실패 단계: 다운로드/체크섬/설치/로그인/테스트메일/dry-run/status/stop/update/uninstall
화면에 표시된 짧은 오류 문구:
재현 횟수: 1회 또는 반복
같은 공인 IP에서 다른 Helper 실행 여부: 없음/있음/모름
prickly-imax diagnose 결과: 개인정보가 제거된 JSON만 첨부
```

제출 이후 상태가 `unknown_after_submit`이면 참가자에게 재시작이나 재설치를 안내하지 않는다. 먼저 CGV 모바일티켓을 본인이 확인하게 하고 자동 재시도는 금지한다.

## 파일럿 성공 조건

- 세 명 모두 Notion만으로 설치·로그인·감시 시작·상태 확인·중지·업데이트·삭제를 완료한다.
- 테스트 이메일이 각 참가자의 자기 주소로 도착한다.
- 자격 증명과 결제 정보가 DM, Notion, GitHub, 로그에 남지 않는다.
- 실패가 발생해도 redacted `diagnose`만으로 단계와 상태를 구분할 수 있다.
- 동일 공인 IP에서 두 Helper가 동시에 실행되지 않는다.

세 명 중 한 명이라도 개발자 개입 없이는 진행할 수 없으면 베타 성공으로 표시하지 않고 Notion 또는 설치 흐름을 수정한 뒤 다시 검증한다.
