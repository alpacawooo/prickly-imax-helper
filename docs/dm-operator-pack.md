# Prickly IMAX Helper DM 운영 문구

이 문서는 Prickly AI 콘텐츠에 DM을 보낸 사람을 비공개 베타로 안내할 때 쓰는 운영자용 복사 문구다. `0.1.0`이 게시되기 전에는 설치 링크를 보내지 않고 대기 등록만 받는다.

## 1. 첫 답장 — 기기 조건 확인

```text
Prickly IMAX Helper 비공개 베타 신청 고마워요.

아래 4가지만 번호대로 답해주세요.
1) macOS / Windows 10·11 중 무엇을 쓰나요?
2) Mac은 Apple Mail, Windows는 클래식 Outlook 데스크톱을 사용할 수 있나요?
3) 비공개 GitHub 초대를 받을 GitHub 사용자명은 무엇인가요?
4) 같은 집·회사 Wi-Fi에서 다른 Prickly Helper를 동시에 실행하지 않는 데 동의하나요? (네/아니요)

CGV 아이디·비밀번호, 관람권 번호, 카드번호, 이메일 주소나 이메일 비밀번호는 DM으로 보내지 마세요. 로그인과 이메일 주소 입력은 본인 PC의 전용 Chrome·로컬 설정창에서만 합니다.
```

본인 CGV 계정과 필요한 수량의 IMAX 관람권 보유 여부는 `있음/없음`만 확인한다. 계정명이나 관람권 번호를 받지 않는다.

## 2. 출시 전 적합자 대기 답장

```text
기기 조건 확인됐어요. 지금은 1시간 안정성 검증 중이라 설치 파일을 먼저 보내지 않고 비공개 파일럿 대기 명단에만 등록할게요.

검증이 끝나면 GitHub 초대 → Notion 3분 설치 안내 순서로 한 번에 보내드릴게요. 비밀번호나 결제정보는 앞으로도 DM으로 보내지 마세요.
```

## 3. 파일럿 활성 초대 답장

아래 문구는 1시간 soak가 통과하고 `0.1.0` 릴리스가 게시된 뒤에만 사용한다.

```text
비공개 베타 초대를 보냈어요.

1) GitHub 알림에서 alpacawooo/prickly-imax-helper 비공개 저장소 초대를 수락해 주세요.
2) 그다음 이 Notion 안내만 보고 설치해 주세요.
https://app.notion.com/p/3b24fb8e6f4d81168194f4f4a4b68bef
3) 제가 화면을 대신 누르거나 명령을 추가로 설명하지 않아도 어디까지 되는지 확인하는 테스트예요.

CGV 로그인은 전용 Chrome에서 직접 하고, 비밀번호·관람권 번호·카드정보는 어디에도 보내지 마세요. 문제가 생기면 전체 화면 대신 Notion의 doctor/diagnose 결과만 보내주세요.
```

## 4. Windows 새 Outlook 사용자 답장

```text
현재 0.1.0은 Windows의 클래식 Outlook 데스크톱을 로컬 메일 발송 통로로 사용해요. 새 Outlook만 사용하는 환경은 이번 파일럿 대상에 포함할 수 없습니다. Windows 알림 자체와 별개로 테스트 메일 검증이 필수라서, 클래식 Outlook을 사용할 수 있을 때 다음 파일럿으로 안내할게요.
```

관리자 PowerShell로만 설치 가능한 사람도 Windows 표준 사용자 검증 참가자로 세지 않는다.

## 5. 완료 확인 답장

```text
아래 항목만 번호대로 알려주세요. 이름·이메일·IP 주소는 보내지 않아도 됩니다.
1) 설치/로그인/테스트메일/dry-run/status/stop/update/restart/uninstall 완료 여부
2) 개발자 설명 없이 Notion만 보고 완료했는지
3) 같은 공인 IP에서 다른 Helper가 실행되지 않았는지
4) diagnose 결과에서 이메일·고객번호·관람권 번호가 제거돼 있었는지

오류가 있었다면 전체 화면 대신 개인정보가 제거된 diagnose JSON만 보내주세요.
```

## 6. 운영자 처리 순서

1. GitHub 사용자명만 별도 초대 목록에 기록하고 A/B/C 증거 JSON에는 기록하지 않는다.
2. A·B는 macOS, C는 Windows 10/11 표준 사용자로 구성한다.
3. 세 명의 수신 서비스는 Gmail·네이버·iCloud·기타 중 서로 다르게 배정한다.
4. 동일 공인 IP 동시 실행 가능성이 있으면 초대 시간을 분리한다.
5. 참가자 완료 후 `scripts/pilot_audit.py verify`가 `ok: true`인지 확인한다.
6. 한 명이라도 개발자 개입이 필요했거나 실패 증거가 불충분하면 릴리스를 게시 완료로 표시하지 않는다.
