# Prickly IMAX Helper 비공개 베타 제작 워크플로우

## 1. 목표와 사용자 경험

콘텐츠를 본 사용자가 DM으로 Notion 링크를 받은 뒤 아래 과정만으로 자기 Mac에서 감시를 시작하게 만든다.

1. 버전이 고정되고 체크섬이 검증되는 설치 명령 한 줄 실행
2. 자동으로 열린 로컬 설정 페이지에서 CGV 전용 Chrome 창 열기
3. 사용자가 CGV에 직접 로그인
4. Odyssey 기본 조건을 확인하고 자기 이메일 주소 입력
5. 자동 예매 범위와 1회 제출 조건에 명시적으로 동의
6. 감시 시작
7. 성공, 중단, 로그인 만료, 복구 필요 상태를 Apple Mail로 통지

독립 실행형 로컬 런타임이 본체다. Codex 플러그인은 자연어 설정, 상태 확인, 진단을 돕는 선택 기능이며 실행 필수 조건이 아니다.

## 2. 변경 불가능한 안전 계약

- 모든 CGV 로그인 정보, 쿠키, 관람권 상태, 이메일 주소는 사용자 Mac에만 둔다.
- CGV 아이디, 비밀번호, 카드번호를 프롬프트, DM, Notion, GitHub, 로그로 받거나 저장하지 않는다.
- 전체 프로세스가 공유하는 요청 제한기를 사용해 동일 IP에서 CGV 요청 시작 간격을 최소 1초로 강제한다.
- HTTP 429를 받으면 즉시 조회를 멈추고 서버 지시 또는 지수형 쿨다운을 적용한다. 짧은 반복 재시도는 금지한다.
- 현재 열린 날짜를 고정 목록으로 저장하지 않고 주기적으로 다시 발견한다.
- 동일 행의 정확히 붙은 좌석만 후보로 인정한다. 허용 행, 가장자리 제외율, 시간 조건을 조용히 완화하지 않는다.
- 결제 직전 영화, 극장, 포맷, 날짜, 회차, 인원, 좌석, 기존 예매, 관람권 수, 잔액을 다시 검증한다.
- 사용자가 사전동의한 방식과 수량이 정확히 일치하고 추가 결제 잔액이 0원일 때만 최종 제출한다.
- 성공 또는 결과 불명 상태가 되면 감시를 멈춘다. 제출 이후 결과가 불명확하면 절대 자동 재제출하지 않는다.
- 기존 예매 취소, 좌석 변경, 중복 예매는 어떤 복구 경로에서도 수행하지 않는다.

## 3. 구현 순서와 단계별 완료 기준

### 단계 A — 배포 가능한 코어

- 사용자 홈 아래 `~/.prickly-imax-helper/`만 사용하는 경로 계약을 만든다.
- 설정, 상태, 로그, 브라우저 프로필을 분리하고 민감 파일 권한을 `0600`, 디렉터리를 `0700`으로 제한한다.
- 설정 스키마와 상태 머신을 코드로 고정한다.
- 단일 인스턴스 잠금과 브라우저 작업 잠금을 분리한다.
- 전역 요청 예산, 429 쿨다운, 날짜별 순환 스케줄러를 구현한다.

완료 조건: 개발자 절대경로와 개인 식별자가 없고, 단위 테스트에서 초당 1회 제한과 429 이후 중단이 증명된다.

### 단계 B — 전용 Chrome과 로그인 유지

- 기존 개인 Chrome과 분리된 프로필을 사용하고 임의의 사용 가능 CDP 포트를 선택한다.
- LaunchAgent가 로그인 세션 이후 Chrome과 런타임을 복구하되 중복 프로세스를 만들지 않게 한다.
- 로그인 여부는 화면의 계정 상태로 확인하고 자격 증명을 읽지 않는다.
- Chrome 종료, 포트 충돌, 로그인 만료를 구조화된 상태로 보고한다.

완료 조건: 재부팅 후에도 전용 프로필이 유지되고, 로그인 만료 시 결제 흐름으로 진입하지 않는다.

### 단계 C — 조회와 좌석 선택

- 영화·극장·포맷을 확인하고 현재 열린 날짜를 동적으로 수집한다.
- 모든 날짜를 한 번에 폭주시켜 조회하지 않고 날짜별로 순환한다.
- 회차 변경을 감지한 경우에만 필요한 좌석표를 조회한다.
- 날짜 버튼은 합쳐진 텍스트가 아니라 요일과 날짜 하위 요소를 각각 읽는다.
- 극장 선택창이 이미 열렸는지 먼저 확인하고, 같은 이름의 검색 제안과 실제 극장 행을 구분한다.
- 좌석표를 다시 읽은 뒤 정책 엔진으로 후보를 정렬하고 선택 직전 같은 좌석이 여전히 사용 가능한지 확인한다.

완료 조건: 동적 날짜, 시간 규칙, 행·가장자리·연속성·중앙 우선순위가 fixture 테스트와 브라우저 dry-run을 모두 통과한다.

### 단계 D — 사전동의형 1회 자동 예매

- 설정 페이지에서 자동 제출 범위, 영화, 인원, 관람권 종류와 수량, 최대 추가 잔액을 명시하고 동의 시각을 기록한다.
- 모바일티켓 목록으로 중복 예매 방지 검사를 시작 시점과 제출 직전에 수행한다.
- 정확한 IMAX 관람권 수와 0원 잔액을 독립 검증한 뒤 고유한 최종 버튼이 하나일 때만 한 번 클릭한다.
- 완료 화면과 모바일티켓을 교차 확인한다.
- 클릭 전 실패는 안전하게 해제할 수 있지만, 클릭 후 통신 오류는 `unknown_after_submit`으로 정지한다.

완료 조건: 성공, 좌석 소실, 관람권 부족, 잔액 발생, 중복 예매, 최종 결과 불명 시나리오가 모두 fail-closed로 끝난다.

### 단계 E — 비개발자 설치와 운영

- 설치 명령은 릴리스 버전을 고정하고 다운로드 SHA-256을 검증한 뒤에만 실행한다.
- 로컬 설정 페이지는 외부 네트워크에 바인딩하지 않고 `127.0.0.1`에서만 열린다.
- 설치, 시작, 상태, 중지, 로그 진단, 업데이트, 삭제 명령을 제공한다.
- Apple Mail에 이미 로그인된 계정으로 사용자가 입력한 자기 주소에 결과를 보낸다. 메일 계정 비밀번호는 받지 않는다.
- 삭제 전 대상 경로와 유지할 브라우저 프로필 여부를 보여주고 명시적 확인을 받는다.

완료 조건: 깨끗한 macOS 사용자 계정에서 Notion만 보고 설치·로그인·시작·중지·삭제가 가능하다.

### 단계 F — 비공개 베타와 공개 게이트

- 비공개 GitHub 저장소에 세 명의 파일럿 사용자를 초대한다.
- 각 사용자는 서로 다른 Mac에서 동일한 온보딩을 수행한다.
- 오류 보고에는 상태 코드, 버전, redacted 로그만 포함한다.
- 공개 전 승인일, 허가 범위, 승인 문서 SHA-256 지문을 릴리스 메타데이터에 기록한다.
- 공개 전 24시간 연속 감시, 429 없음, 중복 프로세스 없음, 메모리 증가 없음, 제출 후 재시도 없음 조건을 확인한다.

완료 조건: 세 명 모두 개발자 설명 없이 감시 시작에 성공하고, 실패 시 Notion 안내만으로 복구하거나 정확한 오류 묶음을 제출한다.

## 4. 자주 발생했던 실수와 방지 규칙

- **날짜 범위 고정:** 8월 5일~18일 같은 값을 코드에 넣지 않는다. 열린 날짜 목록 자체를 갱신한다.
- **과도한 병렬 조회:** 3초마다 모든 날짜를 동시에 요청하지 않는다. IP 단위 전역 제한기와 공정한 순환 큐를 통과시킨다.
- **429 즉시 재시도:** 반복 재시도가 차단 시간을 늘린다. 한 번의 429도 전역 쿨다운으로 처리한다.
- **극장 선택 모달 토글:** 이미 열린 모달의 버튼을 다시 눌러 닫지 않는다.
- **동일 극장명 오선택:** 검색 제안과 실제 극장 행을 DOM 역할과 확인 버튼 활성화로 구분한다.
- **날짜 텍스트 추측:** `목 06`처럼 공백을 추측하지 않고 별도 요소를 읽는다.
- **감시와 결제의 탭 충돌:** 상태 확인까지 포함한 모든 브라우저 조작이 동일 잠금을 사용한다.
- **좌석 발견값 신뢰:** 감시에서 찾은 좌석을 바로 누르지 않고 결제 탭에서 재검증한다.
- **중복 예매 검사 한 번만 수행:** 시작 시 검사만 믿지 않고 제출 직전에 다시 검사한다.
- **0원 문구 하나만 신뢰:** 선택한 관람권 수, 총액, 남은 잔액, 최종 버튼을 각각 확인한다.
- **제출 성공 추정:** 버튼 클릭으로 성공을 선언하지 않고 모바일티켓 생성까지 확인한다.
- **결과 불명 재시도:** 결제 후 응답 유실은 실패가 아니다. `unknown_after_submit`으로 정지한다.
- **개인 코드 복사:** 개인 경로, 고객번호, 쿠키, CDP 포트, 관람권 정보를 공개 런타임에 복사하지 않는다.
- **LaunchAgent PATH 착각:** 대화형 셸 PATH를 기대하지 않고 실행 파일 절대경로를 설치 시 확정한다.
- **설치 명령 최신 브랜치 사용:** `main`을 바로 실행하지 않고 태그·체크섬이 일치하는 릴리스만 설치한다.
- **민감 로그 노출:** DOM 전체, 쿠키, 요청 헤더, 고객번호, 관람권 번호를 로그에 남기지 않는다.
- **권한 과다 요청:** 접근성·전체 디스크 접근을 기본 요구하지 않고 실제 필요한 권한만 안내한다.

## 5. 테스트 매트릭스

- 정책: 요일별 시간 경계, 행별 다른 좌석 수, 가장자리 반올림, 연속 2석, 중앙 동률
- 스케줄러: 초당 1회, 여러 날짜 공정성, 재시작 후 예산 유지, 429 쿨다운, 서버 `Retry-After`
- 브라우저: 모달 열린 상태, 중복 극장명, 날짜 DOM 변경, 로그인 만료, Chrome 종료, 포트 충돌
- 결제: 좌석 소실, 관람권 0·1·2·3매, 잔액 0원·양수, 최종 버튼 0·1·2개, 기존 티켓 존재
- 결과: 모바일티켓 성공, 성공 화면만 존재, 응답 유실, 프로세스 강제 종료 후 재기동
- 설치: 신규 설치, 같은 버전 재실행, 업그레이드, 롤백, 제거, 사용자 데이터 유지·삭제 선택
- 개인정보: 저장소와 릴리스 아카이브 비밀정보 스캔, 로그 redaction, 파일 권한, localhost 바인딩

## 6. 릴리스 승인 조건

다음 중 하나라도 실패하면 비공개 베타 배포 또는 공개 전환을 하지 않는다.

- 플러그인·스킬·설정 스키마·런타임 테스트 미통과
- IP당 초당 1회 제한이 모든 프로세스에 걸쳐 보장되지 않음
- 429 이후 계속 요청하는 경로 존재
- 추가 결제 잔액이 있는데 제출 가능한 경로 존재
- 중복 예매 또는 제출 결과 불명 상태에서 재시도 가능한 경로 존재
- 개인정보나 개발자 로컬 경로가 저장소 또는 릴리스에 포함됨
- 설치 아카이브 체크섬 검증 누락
- CGV 승인 범위와 승인 문서 지문 기록 누락
